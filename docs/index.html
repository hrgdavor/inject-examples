2A declaration, and how much of it comes along

When the file carries no region directive, the name is looked for as a declaration — a method, constructor or class-like block. The declaration *is* the region, so the file needs nothing added to it. A -, + or ++ segment after the path selects how far up the text starts:

  • #toString — the declaration: signature through closing brace.
  • #toString/- — the body only, without the signature.
  • #toString/+ — the declaration and the annotations above it.
  • #toString/++ — those and the doc comment above them.

The modifier is the last segment of the path and nothing else, so #toString- is the name toString- and resolves to nothing, and the old spelling says so: "++" is a path segment now; write "#toString/++".

package demo;

import java.util.ArrayList;
import java.util.List;

/** A small stock inventory: the sample every target on this page reads. */
public class Inventory {

    // #region catalog
    /** The catalog, kept as an explicit region directive. */
    static final String[] CATALOG = { "bolt", "nut", "washer" };
    // #endregion

    private final List<Item> items = new ArrayList<>();

    /** One stock line of this inventory. */
    public static class Item {
        private final String name;
        private final int quantity;

        Item(String name, int quantity) {
            this.name = name;
            this.quantity = quantity;
        }

        /** Render one line the way the receipt shows it. */
        String render() {
            return name + " x" + quantity;
        }
    }

    /** Summarise the inventory. */
    @Override
    public String toString() {
        return items.size() + " item(s)";
    }

    /** Run one named method. */
    public void dispatch(String methodName) {
        if ("count".equals(methodName)) {
            System.out.println("items: " + items.size());
        } else if ("clear".equals(methodName)) {
            items.clear();
        }
    }

    public void legacy() { //count
        System.out.println("items: " + items.size());
    }
}

Its nesting is the path, so the rule inside the media query is reached as a child of the at-rule:

samples/site.css#@media/.card/-inject

grid-template-columns: 1fr 1fr;

An at-rule with a name of its own — @keyframes:pulse names one animation, @keyframes alone would be an error here because the file has two:

samples/site.css#@keyframes:pulseinject

@keyframes pulse {
  from {
    opacity: 0.4;
  }
  to {
    opacity: 1;
  }
}

A region directive still works in CSS, and a class name cannot be a region name, so the two never collide:

samples/site.css#pulseinject

@keyframes pulse {
  from {
    opacity: 0.4;
  }
  to {
    opacity: 1;
  }
}

Line numbers, and several pieces at once

A reference may name lines directly instead of a block, which is the tool for a file whose structure the matchers cannot see — a config fragment, a log, a table in a comment. #L<line> is one line, #L<line>:<column> starts at a column, and #L40-L44 / #L40:12-L44:3 are ranges; lines and columns are counted from 1 and the two ends are inclusive, exactly as an editor shows them.

Inventory.java lines 8-14 are the blank line under the class header and the field below the catalog region:

samples/Inventory.java#L8-L14inject


    // #region catalog
    /** The catalog, kept as an explicit region directive. */
    static final String[] CATALOG = { "bolt", "nut", "washer" };
    // #endregion

    private final List<Item> items = new ArrayList<>();

A comma puts several selectors in one reference, and the pieces are injected in the order they were written — a semantic name and a line range mix freely. The class opening, then the documented toString and its body, then the last line of the file. The middle column highlights each piece on its own, so the lines between them stay unlit — a click lands on the two places the reference names, not on everything between:

samples/Inventory.java#L7,toString/++,L50inject

public class Inventory {
    /** Summarise the inventory. */
    @Override
    public String toString() {
        return items.size() + " item(s)";
    }
}

JSON — keys

JSON renders a selection of keys as valid JSON, in the order they were named, with nested keys and array elements addressable by / — the same separator a code reference uses.

samples/api.json#name,server/portinject

{
  "name": "cart-api",
  "server": {
    "port": 8080
  }
}
